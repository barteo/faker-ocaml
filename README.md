# faker (OCaml)

This is an OCaml port of [@faker-js/faker](https://github.com/faker-js/faker) **10.6.0**, which
generates large amounts of realistic fake data for tests and development.

- **Seed-for-seed parity.** For the same seed, every method returns the same value faker-js
  returns. The library uses the same MersenneTwister19937 generator and the same algorithms,
  and `dune test` checks this against fixtures generated by running faker-js itself.
- **All 26 modules** are ported: airline, animal, book, color, commerce, company, database,
  datatype, date, finance, food, git, hacker, helpers, image, internet, location, lorem, music,
  number, person, phone, science, string, system, vehicle and word.
- **English locale** (`en` + `base`). Locale data is generated from the npm package, so other
  locales can be added with `node tools/gen_locale.mjs <locale>`.
- The library depends only on the stdlib and `unix`.

## Usage

```ocaml
let () =
  let f = Faker.create ~seed:42 () in
  print_endline (Faker.Person.full_name f);                      (* Nikita Crist *)
  print_endline (Faker.Location.street_address ~use_full_address:true f);
  print_endline (Faker.Internet.email f);
  print_endline (Faker.String.uuid f);
  Printf.printf "%d\n" (Faker.Number.int ~min:1 ~max:10 f);
  print_endline (Faker.Helpers.fake "{{person.firstName}} likes {{food.fruit}}" f);
  print_endline (Faker.Helpers.from_reg_exp "[A-Z]{3}-[0-9]{4}" f)
```

### Conventions

| faker-js | OCaml |
|---|---|
| `faker.person.firstName({ sex: 'female' })` | `Faker.Person.first_name ~sex:`Female f` |
| `faker.number.int({ min: 1, max: 10 })` | `Faker.Number.int ~min:1 ~max:10 f` |
| `faker.string.alpha({ length: { min: 3, max: 5 } })` | `Faker.String.alpha ~length:(`Range (3, 5)) f` |
| `faker.helpers.arrayElement(arr)` | `Faker.Helpers.array_element arr f` |
| `new Faker({ locale: [en, base], seed })` | `Faker.create ~seed ()` |
| `faker.seed(42)` | `Faker.seed f 42` |
| `faker.setDefaultRefDate(date)` | `Faker.set_default_ref_date f ms` |

- The faker instance always comes last, and options are optional labelled arguments in
  snake_case.
- A `NumberOrRange` option becomes `` `N n `` or `` `Range (min, max) ``. String unions become
  polymorphic variants.
- Dates are `float` epoch milliseconds. Use `Faker.Date_util.to_iso` and `of_iso` to convert.
- Errors raise `Faker.Faker_error msg`, with the same messages as faker-js.

## Development

```sh
opam install dune alcotest
dune build
dune test                       # parity fixtures + property tests
ONLY=person dune test --force   # one module's parity fixtures
dune exec ./bin/demo.exe -- 42  # one value per module
```

Fixtures come from the real faker-js package (`tools/package.json` pins 10.6.0):

```sh
cd tools && npm install
node gen_locale.mjs             # lib/locales/{en,base}_data.ml
node gen_fixtures.mjs [group]   # test/expected/expected_<group>.ml from tools/cases/<group>.mjs
```

See [docs/PORTING.md](docs/PORTING.md) for the porting conventions and the parity pitfalls,
such as FMA contraction on arm64, UTF-16 vs UTF-8, and JS number formatting.

## Known differences

- `number.bigInt` uses native 63-bit `int`, so ranges wider than about 4.6e17 raise an error.
- Date strings are parsed as ISO 8601. A date-time string without a timezone offset is read as
  UTC, while JS reads it as local time.
- `finance.amount ~auto_format:true` always formats as en-US.
- Through `helpers.fake`, a date-returning method yields an ISO string. JS would produce its
  locale-dependent `Date.toString()`.
- `location.nearbyGPSCoordinate` uses a port of V8's fdlibm `sin`/`cos`, which is bit-exact
  with node on arm64.
