# Porting guide (faker-js 10.6.0 → OCaml)

The goal is **seed-for-seed parity**: given the same seed, every method returns exactly what
`@faker-js/faker@10.6.0` returns. That means every RNG call must happen in the same order with the
same arguments, so port each upstream method **line by line**. Don't "simplify" it.

Upstream source (read-only reference):
`/private/tmp/claude-501/-Users-barteo-projects-tmp-claude-code/b75229f9-6506-4df9-820a-6c5b7a32d165/scratchpad/upstream/faker/src`
(`modules/<m>/module.ts`, `locales/en/<m>/*.ts`, `locales/base/...`).

Toolchain: run `eval $(opam env --switch=default)` first. Then `dune build` and `dune test`.

## Layout

| Path | Purpose |
|---|---|
| `lib/modules/fk_<m>.ml` | The port of upstream module `<m>`, exposed as `Faker.<M>` (see `lib/faker.ml`). |
| `lib/internal/` | Shared infrastructure: `Core`, `Locale`, `Json`, `Js`, `Args`, `Registry`, `Date_util`, `Unicode`. |
| `tools/cases/<m>.mjs` | Fixture cases: `export const cases = [[id, (f) => f.<m>.method(opts)], ...]` |
| `test/cases/cases_<m>.ml` | The same ids mapped to OCaml closures `Faker.t -> Json.t` (helpers in `test/cases/t.ml`). |
| `test/expected/expected_<m>.ml` | GENERATED by `node tools/gen_fixtures.mjs <m>` (run inside `tools/`). |

Run one group with `ONLY=<m> dune test --force`. Each case runs for seeds 42, 1337 and 7, and
calls the method 3 times in a row. JS exceptions are recorded as `{"error": message}`, and the
harness converts `Faker.Faker_error msg` in the same way.

## API conventions

- Signature shape: optional and labelled options come first, then required positional
  arguments, then the faker instance **last**. Example: `first_name ?sex f`,
  `Number.int ?min ?max f`, `Helpers.array_element arr f`.
- Option names are the upstream names in snake_case: `fractionDigits` → `~fraction_digits`,
  `refDate` → `~ref_date`.
- Union or string-literal options become polymorphic variants: `` `Female | `Male``,
  `` `Upper | `Lower | `Mixed`` (see `lib/types.ml`). `NumberOrRange` becomes
  `` Types.range = [`N of int | `Range of int * int] ``.
- Dates are `float` epoch milliseconds. The default reference date is `Core.ref_date f`. Use
  `Date_util` for UTC parts, `Date.UTC`, `to_iso` and `of_iso`.
- JS `bigint` is `Bigint.t` (`lib/internal/bigint.ml`). Its `div` and `rem` follow JS: `/`
  truncates toward zero and `%` takes the sign of the dividend. `BigInt(x)` conversions are
  `Bigint.of_string`, `of_float` and `of_bool`, which raise V8's messages.
- Upstream return types map to `string`, `int`, `float`, `bool`, `'a array`, records, or tuples.
  If a method returns an object, define a small record type in your module.
- When upstream *validates* input and throws, raise with the **exact same message** through
  `Core.error "fmt" ...`. Format numbers with `Js.number_to_string` where JS would stringify a
  number.

## Parity pitfalls (read these)

- **Floating point: never write `a *. b +. c`.** The arm64 backend fuses it into an FMA, which
  rounds differently from JS. Write `Js.mul a b +. c` instead. The same applies to `c -. a *. b`
  and `a *. b -. c`.
- JS `Number.toString`, `toFixed`, `parseInt`, `padStart` and so on are in `lib/internal/js.ml`.
  JS `Math.round(x)` is `Float.floor (x +. 0.5)`, not `Float.round`.
- JS strings are UTF-16 and OCaml strings are UTF-8 bytes. en data is mostly ASCII, but the
  other 76 locales are not, so never use `String.uppercase_ascii` and friends on locale data.
  The JS equivalents are in `lib/internal/unicode.ml`:
  - `toUpperCase` → `Unicode.js_upper`; `toLowerCase` → `Unicode.js_lower` (with the
    final-sigma rule); `s.charAt(0).toUpperCase() + s.slice(1)` → `Unicode.js_upper_first`.
  - `.length` → `Unicode.js_length`; spreads (`[...str]`) → `Js.code_points`.
  - `normalize('NFKD')` → `Fk_internet_nfkd.nfkd` (full table, canonical ordering).
    `Unicode.nfkd` alone only covers the Latin, Greek and Cyrillic blocks.
  - `Number(str)` → `Js.to_number`.
  The tables come from node via `tools/gen_unicode.mjs`. The locale sweeps
  (`ONLY='sweep_*'`, `ONLY='l10n_*'`) catch most mistakes here.
- Array spread or copy, `Object.keys` order, and `.at(-1)` all need care. Keep the evaluation
  order of RNG calls exactly as upstream, including JS's left-to-right evaluation of template
  literals and arguments. OCaml evaluates function arguments **right to left**, so bind each
  random value with `let` before combining.

## Locale data

- `Locale.get f "person" "first_name"` returns a `Json.t`. It raises the upstream "missing data"
  error when the entry is absent.
- `Locale.find` returns an option. `Locale.strings f cat entry` returns a `string array`.
  `Locale.path json ["generic"]` descends into a value.
- Data keys are upstream's own (snake_case) keys. `faker.definitions.x.y` is `Locale.get f "x" "y"`.
- Pick from data with `Fk_helpers.array_element` (or `weighted_array_element` for
  `{value, weight}` lists). Expand `{{...}}` patterns with `Fake.fake pattern f`,
  `Fake.fake_one_of patterns f` or `Fake.fake_json json f`, which mirror
  `this.faker.helpers.fake(...)`.
- Existing modules you can call: `Fk_number`, `Fk_number_bigint`, `Fk_datatype`, `Fk_string`,
  `Fk_helpers` (array_element(s), shuffle, weighted_array_element, multiple, maybe, slugify,
  replace_symbols, replace_credit_card_symbols, luhn_check_value, ...),
  `Fk_helpers_regexp.from_reg_exp`, and `Fake`.

## Registry (for `helpers.fake("{{module.method}}")`)

At the end of each `fk_<m>.ml`, define
`let registry : (string * Registry.fn) list = [ ("camelCaseName", fun f args -> ...); ... ]`
with an entry for **every public method**. Use `Args` to decode JSON options:
`let o = Args.opts ~shorthand:"length" args in ... (Args.int o "min")`, then return a `Json.t`
(`Args.str`, `Args.num`, `Args.int_`, `Json.Arr`, ...). `lib/faker.ml` already registers every
module.

## Fixtures

For every public method, write cases that cover the default call and each meaningful option
variant, including error cases. Use `[id, (f) => ...]` in `tools/cases/<m>.mjs` and the same
`id` in `test/cases/cases_<m>.ml`. Serialize the OCaml result into the JSON that
`JSON.stringify` would produce for the JS result: objects become `Json.Obj` with the same key
order, `undefined` becomes `null`, and Dates become ISO strings via `T.date`.
